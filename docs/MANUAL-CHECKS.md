# Ручные проверки

Автотесты проверяют структуру PPTX, XML и грубую картинку через LibreOffice (`docs/TESTING.md`). То, что
действительно важно — открывается ли файл без «восстановления» и совпадает ли текст с Figma на 1–2 px, — видно
только в настоящих программах. Этот чек-лист — по этапам; отмечайте версию программы и ОС.

Обозначения программ: **Win** — PowerPoint для Windows (Microsoft 365), **Mac** — PowerPoint для Mac,
**KN** — Keynote, **GS** — Google Slides (Файл → Импорт слайдов или открыть PPTX с Диска).

## 0. Подготовка

1. `npm ci && npm run build`; в десктопной Figma: **Plugins → Development → Import plugin from manifest…** →
   `manifest.json`; запуск: **Plugins → Development → FigmaDeck — Export to PPTX**.
2. Тестовый Figma-файл (удобно держать один на все этапы):
   - фрейм 1920×1080 с русским и английским текстом разных стилей: Regular, Bold, Italic, Bold Italic и
     не-RIBBI (Light / Medium / Semibold) одного семейства; letter-spacing в % и px; line-height AUTO, % и px;
     текст с автошириной (WIDTH_AND_HEIGHT), фиксированной шириной и TRUNCATE; маркированный и нумерованный
     списки; ссылка (URL и переход на другой фрейм); UPPER / Title case; верхний индекс;
   - фигуры: прямоугольник, скруглённый, эллипс, линия (пунктир, стрелки, круглые концы), линейный и радиальный
     градиенты, тень, прозрачность слоя и заливки, повёрнутый и отражённый элементы, обводки inside / outside;
   - группа, фрейм с заливкой и радиусом, фрейм с `clipsContent` и прокручиваемым списком, маска, blur, blend mode;
   - картинка FILL, FIT, CROP; векторная иконка; группа мелких иконок;
   - фрейм **4992×1536** («5K wide») и фрейм 1080×1080 (другой размер);
   - секция с двумя фреймами.
3. Для каждого экспорта сохраните рядом PNG тех же фреймов из Figma (Export → PNG 1x) — для сравнения на глаз
   и для `scripts/visual-regression.ts`.

## Этап 1 — MVP: «Точный вид» (фон картинкой + текст)

В Figma:
- [ ] «Добавить слайды» по выделению; фреймы появились в списке, миниатюры рисуются.
- [ ] Настройки → Режим «Точный вид» → Экспорт → PowerPoint. Прогресс идёт, Figma не зависает, файл скачался.
- [ ] После экспорта на холсте не осталось временных слоёв «[FigmaDeck temp]».

В каждой программе (Win / Mac / KN / GS):
- [ ] Файл открывается **без** окна «восстановить» / ошибок импорта.
- [ ] Размер слайда = размер фрейма (Win: Дизайн → Размер слайда → Настроить: 1920×1080 px → 26,667×15″).
- [ ] Фон чёткий (растр 2x), текст лежит поверх и совпадает с PNG из Figma с точностью 1–2 px: переносы строк те же,
      последнее слово в текстах с автошириной не переносится.
- [ ] Текст редактируется; кегль в pt = px в Figma (64 px → 64 pt).
- [ ] Win / Mac: русский текст **не подчёркнут** красным (язык ru-RU: Рецензирование → Язык), английский — en-US.
- [ ] Шрифты: Regular / Bold / Italic / Bold Italic показаны как одно семейство с кнопками Ж / К; Light / Medium /
      Semibold — как «Семейство Начертание». Если шрифт не установлен — PowerPoint подставил замену (это ожидаемо).
- [ ] Межбуквенный интервал и межстрочный интервал (Абзац → Междустрочный: «Точно N пт») как в Figma.
- [ ] Файл → Сведения: заголовок = название презентации, автор / организация из настроек, нигде нет «PptxGenJS».

## Этап 2 — нативные элементы («Редактируемый»)

Экспорт в режиме «Редактируемый», затем в каждой программе:
- [ ] Без «восстановления».
- [ ] Прямоугольники, скруглённые (радиус как в Figma), эллипсы, линии — **фигуры**, а не картинки (выделяются как
      фигуры, есть «Формат фигуры»). Пунктир, стрелки, концы линий на месте.
- [ ] Линейный градиент — редактируемая градиентная заливка, направление и цвета как в Figma; радиальный — картинка.
- [ ] Тень (одна, без spread) — нативная тень фигуры; размытие и смещение примерно как в Figma.
- [ ] Прозрачность слоя и заливки передана (Формат → Заливка → Прозрачность).
- [ ] Группы Figma — группы PowerPoint (Win / Mac: «Разгруппировать» работает; в области выделения видна иерархия
      с именами слоёв из Figma). KN / GS: группы открываются, элементы на местах.
- [ ] Повёрнутые / отражённые элементы стоят как в Figma.
- [ ] Картинка FILL / FIT / CROP: видна как в Figma; Win / Mac: «Обрезка» показывает исходную картинку целиком.
- [ ] Векторная иконка: Win (365) — SVG, чёткая при увеличении, доступно «Преобразовать в фигуру»; Mac / KN / GS —
      PNG-копия без артефактов. Группа мелких иконок — одна картинка.
- [ ] Прокручиваемый список в фрейме с `clipsContent`: за пределами слайда ничего нет (в Deck там лежали сотни
      текстбоксов); частично видимые элементы обрезаны как в Figma.
- [ ] Ссылки: URL открывается; ссылка на другой фрейм — переход к соответствующему слайду (в режиме показа).
- [ ] Отчёт в плагине: маска, blur, blend mode, радиальный градиент перечислены как растеризованные с правильными
      причинами; слои вне клипа — в «Пропущенных».

## Этап 3 — UI и качество

В Figma:
- [ ] Выделение секции добавляет её фреймы; выделение слоя внутри фрейма — сам фрейм; повторное добавление не
      дублирует.
- [ ] Порядок по умолчанию: по рядам, затем слева направо. Перетаскивание миниатюр меняет порядок, «Упорядочить по
      положению на холсте» возвращает автоматический. Двойной клик — фрейм показан на холсте.
- [ ] Список слайдов и название сохраняются в файле (закрыть / открыть плагин и файл). Настройки сохраняются между
      файлами.
- [ ] Удалить фрейм на холсте → в списке он серый, при экспорте пропущен (запись в отчёте).
- [ ] Большой файл (50+ слайдов, много картинок): прогресс идёт, Figma отзывчива, «Отменить» останавливает экспорт.
- [ ] Настройки: масштаб растра 1x / 3x (размер файла и чёткость меняются), JPEG (файл меньше, прозрачные PNG
      остались PNG), «Менять текст» для UPPER, запас ширины 0 % (PowerPoint начинает переносить слова), «Сохранять
      группы» выкл. (всё плоско), «Нативные градиенты» выкл. (градиент — картинка), «Частично обрезанный текст →
      Оставить текстом», «Заливки картинкой → Растеризовать», «SVG для векторов» выкл.
- [ ] Соответствие шрифтов: переопределить строку (другое имя / Ж / К) → в PPTX стоит заданный шрифт; строка
      помечена «вручную»; «Полные имена» → Bold пишется как «Семейство Bold» без Ж.
- [ ] Фрейм **4992×1536**: Win / Mac открывают файл; слайд 56″×17,23″; всё отмасштабировано (кегль 64 px → 51,7 pt);
      в отчёте «Слайд масштабирован».
- [ ] Фреймы разного размера в одной презентации: второй вписан и отцентрован, запись в отчёте.
- [ ] «Размер слайда → Свой» 13,333 × 7,5: все слайды вписаны и отцентрованы.
- [ ] PDF: векторный (текст выделяется, масштабируется без пикселизации), страницы по порядку, размеры фреймов.
      «PDF, только картинки» и «PowerPoint, только картинки» — по картинке на страницу / слайд, файл маленький.
- [ ] IR JSON: скачался `<название>.figmadeck.json`; `npx tsx scripts/fixture-to-pptx.ts <файл>` собирает из него PPTX.
- [ ] Отчёт: «Скопировать отчёт» кладёт текст в буфер; «Скачать ещё раз» работает.
- [ ] Старый файл из Deck шире 4032 px: `node scripts/fix-oversized-pptx.mjs файл.pptx` → `файл_fixed.pptx` открывается
      в PowerPoint.

## Этап 4 — встраивание шрифтов (экспериментальный прототип, в UI не подключён)

Главный открытый вопрос: принимает ли PowerPoint несжатый EOT (`docs/font-embedding.md`, раздел 8).

1. На **машине сборки** сделайте тестовый файл со шрифтом, которого точно нет у получателя (копия Liberation Sans с
   переименованным семейством):

   ```bash
   L=/usr/share/fonts/truetype/liberation
   npx tsx tests/fonts/embed-cli.ts --out probe.pptx --face "FdEmbProbe Sans" --rename Liberation=FdEmbProbe \
     --regular $L/LiberationSans-Regular.ttf --bold $L/LiberationSans-Bold.ttf \
     --italic $L/LiberationSans-Italic.ttf --bold-italic $L/LiberationSans-BoldItalic.ttf
   ```

   (Любой другой TTF: `--face` = имя семейства шрифта, name ID 1 — скрипт его печатает.) Встроить в готовую
   презентацию: `--in deck.pptx`.
2. Откройте `probe.pptx` на машине **без** этого шрифта и отметьте:
   - [ ] Win: без «восстановления»; текст набран встроенным шрифтом (форма букв как у Liberation Sans / Arial, а не
         Calibri / Times); в поле шрифта «FdEmbProbe Sans» без пометки о замене; четыре строки — обычная,
         полужирная, курсив, полужирный курсив — настоящими начертаниями, а не искусственным наклоном / утолщением.
   - [ ] Win: Файл → Параметры → Сохранение → «Внедрить шрифты в файл» включено; «Сохранить как» → файл снова
         открывается на третьей машине с тем же результатом.
   - [ ] Mac (Microsoft 365): то же.
   - [ ] PowerPoint в браузере: результат (не проверялось).
   - [ ] KN, GS: ожидается подстановка другого шрифта (встроенные шрифты игнорируются) — зафиксировать.
   - [ ] LibreOffice ≥ 25.8: шрифт используется (в 24.2 — нет, это известно).
3. Лицензии: сделайте копию шрифта с `fsType = 4` (Preview & Print) — например, в FontForge (Element → Font Info →
   OS/2 → Embeddable: «Printable Document»), встройте через `embed-cli.ts` → в Win файл должен открыться **только
   для чтения** с сообщением про встроенные шрифты с ограничениями. Шрифт с `fsType = 2` скрипт должен отклонить
   (`refused [restricted]`).
4. Если PowerPoint не принимает файл или показывает замену — это аргумент реализовать сжатие MicroType Express
   (как пишет сам PowerPoint); если принимает — можно подключать прототип в UI (раздел 9 в `docs/font-embedding.md`).
