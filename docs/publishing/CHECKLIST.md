       разработки → **Publish**. **[поиск]** (точное название пунктов меню сверить)
4. [x] **ID плагина.** Выдан Figma: `"id": "1686010212254156544"` — уже записан в `manifest.json`
       и закоммичен. Никогда его не меняйте. (Как это было:  Figma покажет в окне публикации ошибку вида «Invalid ID in manifest.json» → нажмите

## 5. Отправка на ревью

- [ ] Нажмите **Publish / Submit for review**. Первый релиз проверяется: плагин появится в разделе Published с
      меткой **In review**; решение придёт письмом на почту аккаунта. **[поиск]**
- [ ] Сроки не гарантированы: «зависят от нагрузки»; на форуме пишут и про один день, и про 2–3+ недели даже для
      простых плагинов без сети. Публичного статуса ревью нет. **[поиск]** Не планируйте анонс на конкретную дату.

**Что проверяют ревьюеры** (по сниппетам review guidelines **[поиск]**, кроме отмеченного):

- основные функции работают, как описано; нет падений и очевидных багов — разработчик должен сам прогнать разные
  сценарии;
- плагин не ухудшает производительность и работу Figma (у нас экспорт идёт батчами, с прогрессом и «Отменить»
  **[код]**);
- плагин не читает и не меняет файл без ведома пользователя; данные защищены; если данные уходят третьим лицам —
  нужны разрешения (у нас не уходят никуда **[код]**);
- доступ к сети объявлен правильно (у нас «нет доступа» **[код]**);
- описание не вводит в заблуждение; нет чужих торговых марок в названии; нет попыток обмануть API;
- аккуратный, профессиональный интерфейс и понятное описание / инструкция — **[не проверено]** как формальный
  пункт guidelines (из постановки задачи), но на практике проверяется.

**Самопроверка перед отправкой** (в чистом Figma-файле, как это увидит ревьюер):

- [ ] запуск без выделения → понятная подсказка, не ошибка;
- [ ] выделить секцию, 1 фрейм, 30+ фреймов; вложенный слой → добавляется его фрейм;
- [ ] все 4 формата экспорта, «Отменить» посреди экспорта, повторный экспорт;
- [ ] фрейм 4992 × 1536, свой размер слайда, отсутствующий шрифт, русский текст;
- [ ] светлая и тёмная тема Figma; язык интерфейса auto / en / ru;
- [ ] закрыть плагин посреди экспорта → на холсте не осталось слоёв «[… temp]»;
- [ ] в консоли (Plugins → Development → Show/Hide console) нет ошибок.

## 7. Монетизация в будущем — только заметки, сейчас ничего не делаем

Сейчас плагин бесплатный; всё ниже — для решения в будущем.

- **Нативные платежи Figma.** **[поиск]**
  - в `manifest.json` добавляется `"permissions": ["payments"]`;
  - `figma.payments.status.type` — `"UNPAID"`, `"PAID"` или `"NOT_SUPPORTED"`; `NOT_SUPPORTED` — внутренняя ошибка,
    платные функции в этом случае **не** открывать;
  - `figma.payments.initiateCheckoutAsync({ interstitial: "TRIAL_ENDED" })` (или без параметров) запускает оплату
    внутри Figma; после неё статус перечитывается;
  - в разработке оплату можно «пройти» без карты — статус меняется локально и сбрасывается после перезапуска
    клиента;
  - для пробного периода есть `figma.payments.getUserFirstRanSecondsAgo()`, для тестов —
    `figma.payments.setPaymentStatusInDevelopment(...)` **[не проверено: по памяти]**.
- **Кто может продавать.** Нужно одобрение Figma как продавца и активированный аккаунт **Stripe** в стране,
  которую поддерживает Stripe; без этого продавать в Community нельзя. **[поиск]** Россию Stripe не поддерживает —
  продавать придётся от юрлица / человека в поддерживаемой стране **[не проверено: по общим сведениям]**. На
  форуме были периоды, когда Figma не принимала новых продавцов (как минимум платных файлов) — проверить текущий
  статус. **[поиск]**
- **Открытые вопросы** **[не проверено]**: можно ли перевести уже опубликованный бесплатный плагин в платный и что
  тогда будет с текущими пользователями; комиссия Figma; подписка или разовая покупка; налоги.
- **Чего не делать:** собственная лицензия через свой сервер потребует доступа к сети и сломает обещание «100 %
  локально, без сети» — и в описании, и в форме Data security.
- Платёжный статус пришлось бы учитывать в `data-security.md` (оплата проходит через Figma, данные карты плагин
  не видит).

## 8. Картинки для страницы

Все картинки рендерятся из HTML/SVG-шаблонов в `src/` headless-Chromium'ом (playwright-core из devDependencies):

```bash
node docs/publishing/src/render.mjs                     # всё: icon.svg, icon-128.png, cover, carousel-01…06
node docs/publishing/src/render.mjs --only cover-1920x1080,carousel-03
node docs/publishing/src/render.mjs --preview           # + лист иконки 16…128 px (во временную папку ОС)
```

- Chromium ищется в `$PLAYWRIGHT_BROWSERS_PATH` или `/opt/pw-browsers` (как у `scripts/ui-screenshots.mjs`),
  иначе — браузер playwright (`npx playwright-core install chromium`).
- Скриншоты интерфейса берутся из `docs/screenshots/*.png` (`npm run ui:screenshots`). После их обновления просто
  запустите `render.mjs` ещё раз. Скрипт печатает, какие скриншоты вошли в какую картинку, отсутствующие рисует
  серой заглушкой и сообщает об этом, а также о тексте, вылезающем за блок или за край картинки (код выхода 1).
- Кропы заданы в логических пикселях окна плагина 1000 × 640 (`data-crop` в шаблонах). Если скриншоты станут 2x
  (≥ 1600 px в ширину), они автоматически рисуются в половину размера — картинки станут чётче без правок шаблонов.
  Если поменяется раскладка интерфейса, поправьте `data-crop` в `carousel-02/04/05.html`.
- Шрифт — Inter (OFL, `src/fonts/`, латиница + кириллица), системные шрифты не нужны.
- Цвета: фирменные цвета Ewento получить не удалось (ewento.app и ewento.ru заблокированы из этого окружения),
  поэтому взята нейтральная палитра — фиолетовый `#5B45F0` / `#8373FF` и янтарный акцент `#FFC14D`
  (`src/base.css`, `src/icon.svg`). Если у Ewento есть брендбук — поменяйте токены в `:root` и цвета в
  `icon.svg`, перерендерите.
